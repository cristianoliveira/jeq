# jeq v0.1.0

jeq v0.1.0 is the first official version of the typed-judgment CLI. Scripts can send one request or process a bounded stream, keep the JSON evidence, and apply offline numeric policy. This release adds clearer input selection and model resolution since v0.1.0-rc.2.

## What's new since rc.2

- `--state-json` now accepts inline JSON. Use `--state-json-file` for a file or selected stdin. `--questions-json` accepts inline questions for `ask`, `validate`, `map`, and `reduce`; `--questions` still reads a file.
- `validate` resolves the same configured model as a composed `ask`, reports where the choice came from, and makes no network request. A native `--request` keeps its embedded model authoritative.
- `--usage-summary` writes successful-request counts, decoded answers, provider-reported tokens, and answers per 1,000 input tokens to stderr for `ask`, `map`, `rate`, `rank`, and `reduce`. Stdout stays machine-readable. Failed requests without usage may still be billed by a provider.
- The custom provider configuration can route requests to a local Laya server on loopback. The [provider guide](../guides/providers.md) covers explicit model selection and offline checks; the [evaluation example](../../examples/laya-evaluation/README.md) shows how to measure quality with a small synthetic corpus. jeq never falls back to a hosted provider on a local error.
- The Go test suite now uses Testify assertions. CLI, domain, infrastructure, black-box, and executable example checks remain in the release gate.

## Upgrade from rc.2

`--state-json FILE` is a breaking change: it now treats `FILE` as inline JSON. Run `--state-json-file FILE` instead. To pass inline state, use `--state-json '{"key":"value"}'`. File and stdin sources remain explicit; jeq does not guess from content.

A native `ask --request` or `validate --request` rejects an explicit `--model` rather than ignoring it. Change the request document's `model` field instead. Use `jeq <command> --help` and `jeq examples <command>` for current copyable invocations.

## Install

Use the archive matching Linux or macOS amd64/arm64 from the [v0.1.0 release](https://github.com/cristianoliveira/jeq/releases/tag/v0.1.0). Verify its SHA-256 against `checksums.txt` before extracting. On Linux, inspect and run [`scripts/install-jeq-linux.sh`](../../scripts/install-jeq-linux.sh) to download and verify the default v0.1.0 archive.

Pin the release with Nix:

```sh
nix run github:cristianoliveira/jeq/v0.1.0 -- version
nix profile install github:cristianoliveira/jeq/v0.1.0
```

The Homebrew tap may lag a newly published release. Run `jeq version` after installing and check the [installation guide](../guides/installation.md) for current choices.

## Known limits

- Judgment commands require an explicitly configured provider and may incur charges. `validate` and `gate` run locally. Never place credentials or private state in committed files or shell history.
- Laya does not expose jeq's `GET /v1/models` endpoint, so `jeq models` cannot discover its models. Choice probabilities are relative, not independent confidence scores. Consult the provider guide before relying on score bands or ranking order.
- `go install ...@v0.1.0` compiles without release linker metadata and reports `dev`/`unknown`; use a verified release archive or pinned Nix package if version and commit metadata matter.
- Windows archives, binary signing, provenance attestations, and nixpkgs publication are not provided in this release.
